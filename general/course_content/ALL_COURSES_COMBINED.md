### Text

The Change Curve
Fortunately people react in fairly predictable ways to change, even if the change is expected. Eventually they accept the change, begin experimenting, and integrating it into their life. The goal of change management is to remove the fear and uncertainty&nbsp;through well-defined communication. You can then alleviate the frustration through training, and help the user embrace the change.

### Text

Embrace change
Effectively managing change means that you helped people by addressing their fears and misconceptions, studied their processes and developed solutions for their challenges, and trained them how to get the most out of the technology.

### Text

Start small, then spread through success
One way to address this is to start by winning over a few key people. Then spreading to engage more people in the organization, with your original successes able to be used as case studies.

### Text

The change journey
Change management isn't an isolated process, it begins within the sales cycle but continues into delivery. The Gemini Enterprise&nbsp;change management methodology will help you to address the challenges around change management. The change journey to long-term success begins with preparation&nbsp;and is then followed by&nbsp;four key&nbsp;phases - Excite, Activate, Expand, and Transform. Each phase is crucial for setting up your customers for success, so make sure you don’t discount early preparation and communication, or analyzing success metrics long after go-live.

Connector and Data Ingestion Project stakeholder security team raises concerns about the scope of permissions required by a connector, delaying or blocking its use. Socialize connector permission requirements with project stakeholder security teams early. Be prepared to discuss permission rationale and alternatives (for example&nbsp;data migration to Google Cloud Storage, limiting scope). Connector and Data Ingestion Syncing on-premises data sources is significantly delayed by network connectivity, firewall rules, or private connectivity setup issues. Rigorously verify all network prerequisites before starting. Allocate specific buffer time in the project plan for debugging private/on-premises connectivity. Connector and Data Ingestion Initial data sync for connectors with very large data volumes (such as&nbsp;extensive Slack history, large document repositories) takes excessively long. Work with the project stakeholder to define a smaller, priority data subset for initial sync to speed up evaluation. Set clear expectations on full sync duration. Explore phased rollout if feasible. Connector and Data Ingestion Ingestion or indexing failures for specific file types or content exceeding limits (for example&nbsp;very large spreadsheets, high-resolution images). Document known limitations on file sizes and types for internal reference and expectation setting. Advise project stakeholders on pre-processing or segmenting large content if necessary. Delivery and Dependencies Project stalls due to lack of timely project stakeholder responsiveness (such as&nbsp;providing system access, data for evaluation, ACL/IDP resolution). Clearly define project stakeholder dependencies and required timelines in the project plan. Escalate risks of non-responsiveness to the project sponsor. Identify key project stakeholder contacts early. Delivery and Dependencies Significant project time is consumed by debugging connector sync or search quality issues due to limited error messages or logs. Budget for debugging cycles. Familiarize the delivery team with available advanced debugging guides and tools. Foster a strong feedback loop with Product and Engineering for recurring or complex issues. Search Functionality Search results do not meet project stakeholder expectations for accuracy or relevance for specific connectors or query types. Custom data connectors
Customers can now develop custom data connectors . Custom connectors work by using an automated data pipeline to perform three key actions: Fetch, Transform, and Sync. This process ensures external data is correctly prepared and uploaded to Gemini Enterprise.

### List

Fetch : The connector pulls data, including documents, metadata, and permissions, from external system using its APIs, databases, or file formats.

Transform : The connector converts raw data into the document format of the Discovery Engine, structures the content and metadata, and assigns a globally unique ID to each document. For access controls, you can use either Google-recognized identities directly or identity mapping for external users or custom groups.

Sync : The connector uploads the documents to Gemini Enterprise data stores and keeps them updated through scheduled jobs. The data sync is performed using a data store created for an entity. You can find more information about creating data stores by following the&nbsp; Data store creation process . Choose a sync mode based on your needs: Incremental adds and updates data, while Full replaces the entire dataset.

Accessing data with ingestion or federation

### Image

When architecting Gemini Enterprise access to enterprise data stored in third-party systems (not on Google Cloud or in Google Workspace data stores), you may be asked to choose between two primary data retrieval patterns, namely, Ingestion or Federation .

### Text

Data Ingestion
With data Ingestion, your data, along with its associated Access Control Lists (ACLs), is actively pulled from the source systems and securely indexed into dedicated Data Stores within Google Cloud.

### Text

Because the data is stored and processed natively within the Google Cloud perimeter , this method typically yields the fastest query latency . The system respects the ingested ACLs at query time, ensuring users only receive answers generated from documents they have explicit permission to view .

### Text

Search Federation&nbsp;
Search Federation, also known as real-time or live federation , leaves your data entirely within its original source system .

### Text

Instead of indexing the data beforehand, Gemini Enterprise translates the user's prompt into a live query against the external system's API. The external system processes the query , enforces access controls natively, and returns the relevant data back to Gemini Enterprise to ground the final response.

This zero-copy architecture is highly advantageous for organizations dealing with strictly regulated , highly sensitive , or rapidly changing data where creating a secondary index is not permissible. It also avoids the duplicate storage costs and managing additional periodic data ingestion complexities .

### Text

Taking actions
The capabilities of Gemini Enterprise extend beyond retrieving and summarizing information as it is also designed to execute tasks .&nbsp; Some Google-provided data stores allow you to enable actions, which allow Gemini Enterprise to make OAuth-authenticated calls to external tools and APIs on a user’s behalf. You can ask Gemini to:

### List

draft and send emails,

schedule calendar events, or

update bug tickets in third-party tracking systems directly from the chat interface.

### Text

The "old way" (the anti-pattern) In the past, you might have solved this by using Google Cloud Identity (GCI) .

### List

You create 500 new Google accounts (such as, dev1@globaltech.com ) or use Google Cloud Directory Sync (GCDS) to keep the accounts in sync.

If you create 500 new Google accounts then you would need to email the credentials to 500 people.

### Text

Why this fails

### List

Security Risk : If a developer leaves PartnerCorp, their Okta account is disabled, but their GlobalTech Google account might remain active (a "Zombie Account").

Overhead : You are now managing the lifecycle of 500 extra users.

Cost : Depending on your license, you might pay for these identities.

User Friction : The developers hate it. They have to manage a second set of credentials and 2FA tokens.

### Text

The Solution: Workforce Identity Federation
To grant 500 new, external users from PartnerCorp access,&nbsp;Workforce Identity Federation is the preferred solution because it shifts from Synchronization (copying users) to Federation (borrowing trust). Instead of creating a user in Google Cloud, you tell Google Cloud: "I trust PartnerCorp’s Okta for these 500 PartnerCorp developers. If PartnerCorp’s Okta says this developer is 'Jamie' and they are allowed to be here, let them in."
