### Text

The Change Curve
Fortunately people react in fairly predictable ways to change, even if the change is expected. Eventually they accept the change, begin experimenting, and integrating it into their life. The goal of change management is to remove the fear and uncertainty&nbsp;through well-defined communication. You can then alleviate the frustration through training, and help the user embrace the change.

### Text

Embrace change
Effectively managing change means that you helped people by addressing their fears and misconceptions, studied their processes and developed solutions for their challenges, and trained them how to get the most out of the technology.

### Text

Start small, then spread through success
One way to address this is to start by winning over a few key people. Then spreading to engage more people in the organization, with your original successes able to be used as case studies.

### Text

The change journey
Change management isn't an isolated process, it begins within the sales cycle but continues into delivery. The Gemini Enterprise&nbsp;change management methodology will help you to address the challenges around change management. The change journey to long-term success begins with preparation&nbsp;and is then followed by&nbsp;four key&nbsp;phases - Excite, Activate, Expand, and Transform. Each phase is crucial for setting up your customers for success, so make sure you don’t discount early preparation and communication, or analyzing success metrics long after go-live.

Develop and share clear documentation or flowcharts for identity management scenarios (first or third party&nbsp;IDP, WIF). Ensure dedicated discussion on ACL strategy and feasibility per connector. Connector and Data Ingestion Project stakeholder security team raises concerns about the scope of permissions required by a connector, delaying or blocking its use. Socialize connector permission requirements with project stakeholder security teams early. Be prepared to discuss permission rationale and alternatives (for example&nbsp;data migration to Google Cloud Storage, limiting scope). Connector and Data Ingestion Syncing on-premises data sources is significantly delayed by network connectivity, firewall rules, or private connectivity setup issues. Rigorously verify all network prerequisites before starting. Allocate specific buffer time in the project plan for debugging private/on-premises connectivity. Connector and Data Ingestion Initial data sync for connectors with very large data volumes (such as&nbsp;extensive Slack history, large document repositories) takes excessively long. Work with the project stakeholder to define a smaller, priority data subset for initial sync to speed up evaluation. Set clear expectations on full sync duration. Explore phased rollout if feasible. Connector and Data Ingestion Ingestion or indexing failures for specific file types or content exceeding limits (for example&nbsp;very large spreadsheets, high-resolution images). Document known limitations on file sizes and types for internal reference and expectation setting. Advise project stakeholders on pre-processing or segmenting large content if necessary. Delivery and Dependencies Project stalls due to lack of timely project stakeholder responsiveness (such as&nbsp;providing system access, data for evaluation, ACL/IDP resolution). Clearly define project stakeholder dependencies and required timelines in the project plan. Escalate risks of non-responsiveness to the project sponsor. Identify key project stakeholder contacts early. Delivery and Dependencies Significant project time is consumed by debugging connector sync or search quality issues due to limited error messages or logs. Budget for debugging cycles. Familiarize the delivery team with available advanced debugging guides and tools. Foster a strong feedback loop with Product and Engineering for recurring or complex issues. Search Functionality Search results do not meet project stakeholder expectations for accuracy or relevance for specific connectors or query types. Implement a robust evaluation framework (golden datasets). Iterate on system instructions, data chunking, and search controls. Custom data connectors
Customers can now develop custom data connectors . Custom connectors work by using an automated data pipeline to perform three key actions: Fetch, Transform, and Sync. This process ensures external data is correctly prepared and uploaded to Gemini Enterprise.

### List

Fetch : The connector pulls data, including documents, metadata, and permissions, from external system using its APIs, databases, or file formats.

Transform : The connector converts raw data into the document format of the Discovery Engine, structures the content and metadata, and assigns a globally unique ID to each document. For access controls, you can use either Google-recognized identities directly or identity mapping for external users or custom groups.

Sync : The connector uploads the documents to Gemini Enterprise data stores and keeps them updated through scheduled jobs. The data sync is performed using a data store created for an entity. You can find more information about creating data stores by following the&nbsp; Data store creation process . Choose a sync mode based on your needs: Incremental adds and updates data, while Full replaces the entire dataset.
